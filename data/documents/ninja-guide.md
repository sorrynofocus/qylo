# Ninja build system guide

## What Ninja is

Ninja (the `ninja` command) is a small build system focused on speed. It does not decide how to
build software on its own: it reads a `build.ninja` file that lists rules and build edges, and runs
only the commands whose inputs changed. `build.ninja` files are usually generated by a meta build
system such as CMake (`cmake -G Ninja`), Meson or GN, but they can also be written by hand.
The full list of Ninja command-line options is in the Ninja reference (`ninja --help`).

## Ninja: build the default target

Run `ninja` in the directory that contains `build.ninja`:

    ninja

Build in another directory without changing to it first:

    ninja -C build

Use a build file with a different name:

    ninja -f my.ninja

## Ninja: build a specific target

Name one or more targets after the options:

    ninja -C build app
    ninja -C build app tests

## Ninja: parallel jobs and keep going after failures

Run 8 jobs in parallel:

    ninja -C build -j 8

Keep building after failures, stopping only after 10 jobs have failed (0 means never stop):

    ninja -C build -k 10

Do not start new jobs while the system load average is above 4:

    ninja -C build -l 4

## Ninja: verbose output and dry run

Show every full command line while building (useful to see exact clang flags):

    ninja -C build -v

Dry run: print what would be built without running any commands:

    ninja -C build -n

Dry run with full commands:

    ninja -C build -n -v

Only show command output, no progress status:

    ninja -C build --quiet

## Ninja: clean build outputs

Remove all files produced by the build:

    ninja -C build -t clean

Clean only the outputs of one target:

    ninja -C build -t clean app

Clean the outputs of a specific rule (for example every object built by the `cc` rule):

    ninja -C build -t clean -r cc

Remove outputs left behind by build edges that no longer exist in `build.ninja`:

    ninja -C build -t cleandead

Note: `ninja -t clean` deletes files. Run `ninja -t clean` against the correct build directory.

## Ninja: list targets, rules and commands

List all targets:

    ninja -C build -t targets all

List targets by rule:

    ninja -C build -t targets rule cc

List all rules:

    ninja -C build -t rules

Print every command needed to build a target (without running them):

    ninja -C build -t commands app

List all inputs used to build a target:

    ninja -C build -t inputs app

Show the inputs and outputs of a target:

    ninja -C build -t query app

## Ninja: dependency graph

Output a Graphviz dot graph of a target's dependencies and render it to PNG (needs Graphviz `dot`):

    ninja -C build -t graph app > graph.dot
    dot -Tpng graph.dot -o graph.png

Show dependencies recorded from depfiles (header dependencies):

    ninja -C build -t deps

Find missing dependencies between generated files:

    ninja -C build -t missingdeps

## Ninja: generate compile_commands.json

Write a compilation database for clangd, clang-tidy and other clang tools:

    ninja -C build -t compdb > compile_commands.json

Limit it to commands produced by a rule, for example `cc` and `cxx`:

    ninja -C build -t compdb cc cxx > compile_commands.json

## Ninja: list subtools, debug modes and warnings

List all subtools:

    ninja -t list

Common subtools: `browse`, `clean`, `cleandead`, `commands`, `compdb`, `deps`, `graph`, `inputs`,
`missingdeps`, `query`, `recompact`, `restat`, `rules`, `targets`. On Windows there is also `msvc`.

List debug modes:

    ninja -d list

Debug modes: `stats` (print operation counts and timing), `explain` (explain why each command is
rebuilt), `keepdepfile` (do not delete depfiles), `keeprsp` (do not delete response files),
`nostatcache` (do not cache file timestamps).

Explain why targets are being rebuilt:

    ninja -C build -d explain

Print build statistics:

    ninja -C build -d stats

List warning flags:

    ninja -w list

Make a phony cycle an error:

    ninja -w phonycycle=err

## Ninja: customize progress output

The `NINJA_STATUS` environment variable sets the progress prefix. `%f` is finished edges, `%t` is
total edges, `%e` is elapsed seconds:

    NINJA_STATUS="[%f/%t %es] " ninja -C build

## Ninja: write a build.ninja file by hand (clang example)

A `build.ninja` file has variables, rules and build edges. Rule bodies are indented. This example
compiles two C files with clang, links them into `app`, and has an `emit-ir` target that produces
LLVM IR (`.ll`) for `main.c`:

    cflags = -O2 -Wall

    rule cc
      command = clang $cflags -MMD -MF $out.d -c $in -o $out
      depfile = $out.d
      deps = gcc
      description = CC $out

    rule ir
      command = clang $cflags -S -emit-llvm $in -o $out
      description = IR $out

    rule link
      command = clang $in -o $out
      description = LINK $out

    build obj/main.o: cc src/main.c
    build obj/util.o: cc src/util.c
    build app: link obj/main.o obj/util.o

    build ir/main.ll: ir src/main.c
    build emit-ir: phony ir/main.ll

    default app

Build the program:

    ninja

Build only the LLVM IR:

    ninja emit-ir

On Windows name the output `app.exe` in the link edge (`build app.exe: link ...`).

Key build.ninja syntax:

- `rule NAME` defines a command template. `$in` is the input list, `$out` is the output list.
- `build OUTPUTS: RULE INPUTS` declares a build edge.
- `| deps` after the inputs adds implicit dependencies; `|| deps` adds order-only dependencies.
- `build NAME: phony INPUTS` creates an alias target.
- `default TARGETS` sets what `ninja` builds with no arguments.
- `depfile` and `deps = gcc` (or `deps = msvc` for cl.exe) track header dependencies.
- `pool` limits concurrency for a group of rules; the built-in `console` pool gives a job the terminal.

## Ninja with CMake

Generate a Ninja build with CMake and build it with Ninja:

    cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Release
    ninja -C build

The same build through CMake's driver:

    cmake --build build

Use clang as the compiler with Ninja:

    cmake -S . -B build -G Ninja -DCMAKE_C_COMPILER=clang -DCMAKE_CXX_COMPILER=clang++
    ninja -C build

Build Debug and Release from one build directory with the multi-config generator:

    cmake -S . -B build -G "Ninja Multi-Config"
    cmake --build build --config Release

See the build systems guide for CMake and Makefile details.
